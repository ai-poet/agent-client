# Fork Maintenance

This is a fork of [egoist/waku](https://github.com/egoist/waku) that adds managed
cloud account integration and a built-in, in-daemon agent, and ships under our
own brand. External agent CLIs are not integrated; other native features track
upstream.

## Remotes and branches

| Remote | Points at |
|---|---|
| `origin` | our fork (**must be repointed after creating the org fork** — currently still upstream) |
| `upstream` | `https://github.com/egoist/waku.git` |

| Branch | Role |
|---|---|
| `main` | mirrors `upstream/main`, never edited directly |
| `integration` | our default branch; all local work lands here |

Repoint `origin` once the org fork exists:

```bash
git remote set-url origin https://github.com/<org>/<fork>.git
```

## Weekly upstream merge

Upstream averages ~15 commits/day. Merge weekly — letting it drift makes
conflicts disproportionately worse.

```bash
git fetch upstream
git checkout main && git merge --ff-only upstream/main
git checkout integration && git merge main
```

Conflicts can only appear in the hook points listed below. If a conflict shows up
anywhere else, our change leaked outside its module — move it back into a
dedicated file.

## Design rule

**All new functionality lives in new files. Upstream files get minimal hook
points only** — ideally one to three lines each. This is the only thing keeping
the weekly merge cheap.

### Conflict triage

- A conflict in one of the listed files: reapply the line, tick the row.
- A conflict anywhere else: our change leaked. Move it back into
  `crates/sub2api` or one of our own view files.
- `SETTINGS_PAGES` has a hard-coded length; upstream adding a page turns that
  into a type error rather than a silent break, which is the desired failure.

  draws the same buttons; both files are ours, so this is not a hook point.

## What we deliberately do not touch

- `crates/client-protocol` — the wire contract. Legacy external provider enum
  variants remain deserializable, but only Native is selectable or startable.
  Routing is desktop-local and writes only native settings. Additive protocol
  exceptions are listed in the register above.
- External provider drivers' protocol handling; those drivers are removed.

User data now lives under `~/.cheaprouter` (platform folders `CheapRouter`
/ `CheapRouter Debug`); `sub2api::migrate` renames the legacy `~/.waku` /
`Waku` directories in place at startup, from both the desktop and daemon
entry points.

## Routing contract (built-in agent only)

`sub2api::global_config` writes only the built-in agent's own `settings.json`.
It never detects, installs, imports, configures, restores, or launches an external
agent CLI. Existing CLI files and old takeover records are left alone; legacy
provider variants remain in the wire types solely so saved state still loads.

What feeds `desired_routes`:

- **Custom endpoints** (`sub2api::custom_api` + `sub2api::providers`,
  `~/.cheaprouter/custom-api.json`) describe address, key, wire format, models,
  and alternate domains. Only the three native slots (`native_messages`,
  `native_responses`, `native_chat`) feed routes; legacy CLI slot data is inert.
  `CustomApiConfig::resolved_endpoint` remains the single resolution path, and
  an unresolved `provider_ref` routes nothing rather than using a stale copy.
- **The selected service origin** (`sub2api::gateway_origin`,
  `~/.cheaprouter/gateway-origin.json`) feeds both model traffic and business
  APIs. `api_origin` / `api_client` / `authenticated` resolve it centrally.
  With no explicit choice, a self-hosted credential keeps its own endpoint.
  `Credentials.endpoint` is never rewritten: login, token refresh and logout
  stay on the authentication origin. Switching origin persists the choice,
  reapplies live native session options, invalidates the model, usage, plan,
  announcement, account and model-status caches, and increments
  `CloudAccountState.api_generation` so late answers from the old origin drop.
- **The bound group** can move through `select_cloud_group`, either manually
  or through `sub2api::failover`; the built-in agent receives the corresponding
  gateway key without any CLI group binding.

`sub2api::speedtest` measures candidate origins with bounded concurrency. The
optional Computer Use driver has its own pinned installer; it shares only
generic process/download helpers and does not install Node or agent CLIs.

## Agent core

`crates/agent-core/engine` vendors Sailry's execution state machine, model/stream
contracts, canonical history types, bounded output projection, and their original
host-neutral tests. `store` applies Sailry effects to an in-memory session for the
embedding host. `agent-core/query/src/sailry` adapts the existing ProviderRegistry,
`ToolContext`, tools, `QueryEvent`, checkpoints, and persisted history; the
`agent-bridge` facade and daemon/UI contracts stay unchanged. Node admission,
Turso, Rig, GPUI, and Sailry plugin hosts are outside the port. Copied Node-only
integration tests remain behind `node-tests` and are not a standalone configuration.
